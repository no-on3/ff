## Context

A developer works with FF through the `curl` commands of the getting-started guide. The two prototype CLIs couldn't replace them:
- they uploaded a zip to the object store with the platform's own storage keys, which deployed nothing (the backend deploys from the `code` of `POST /functions`), and which no customer may ever hold (parent finding H-10);
- their zip layout wasn't what the runtimes load, which is Lambda's: the handler at the root of `/var/task`, its dependencies next to it;
- there were two of them, in two languages, for one job.

The platform has changed since. Every route needs a token: a user's Keycloak token, or an API key `ffk_<key ID>_<secret>` with scopes ([ADR 0004](0004-identity-and-tenancy.md)). A function's name is unique in its account and follows Lambda's rule. The logs, metrics, usage and balance have routes. A function gets AWS Lambda's event ([ADR 0007](0007-function-events.md)).

FF's customers are developers in Tunisia, who may install tools from a slow or filtered connection, often behind a company proxy, and who must be able to leave FF for AWS with the same project.

## Decision

### 1. One Rust binary, `ff`, that talks only to the API (D1)
- **Rust,** as the parent's ADR-007 chose: one static binary, installed by copying it, with no Node.js or Python on the machine.
- **The API only.** No storage keys, no kubeconfig, no cluster access: everything goes through the backend's routes, with the caller's token. What the API can't do yet, the CLI doesn't do.
- **Small and blocking.** One request at a time needs no async runtime: `clap` for the commands, `ureq` for HTTP over `rustls` with the operating system's certificate verifier (so a company's own CA and TLS-inspecting proxies work), `HTTPS_PROXY` and `NO_PROXY` honoured; `serde_json`, `toml`, `zip` with `sha2`, `walkdir` and `ignore`. No `tokio`, no S3 client.
- **Static builds** for Linux on x64 and arm64 (musl) first; macOS and Windows with the releases (CLI plan, C-41).

### 2. Configuration (D2)
- `config.toml`, in the system's configuration folder (`~/.config/ff/` on Linux), holds profiles: an endpoint, an account, and in development the account to act as. The tokens are in `credentials.toml` next to it, created with mode 0600 and never printed whole.
- **Precedence:** a flag, then an environment variable (`FF_ENDPOINT`, `FF_PROFILE`, `FF_TOKEN`, `FF_ACCOUNT`), then the profile, then `http://localhost:3000`.
- **No `--token` flag:** a token on a command line ends up in the shell's history. `ff config set-token` reads it from a prompt or stdin.
- **TLS:** plain `http://` only to `localhost` and `127.0.0.1`, unless `--allow-http`.

### 3. Functions are addressed by name, as on Lambda (D3)
`ff invoke hello`, not a UUID. Names are unique in an account and compared exactly, so a name finds one function. The CLI checks Lambda's rule, `^[A-Za-z0-9_-]{1,64}$`, before it sends a name.

### 4. Packages follow Lambda's rules exactly (D5)
- The handler at the zip's root, the dependencies inside it: `node_modules/` for Node.js, the packages at the root for Python.
- Lambda's limits: 50 MB zipped for a direct upload, 250 MB unzipped.
- `CodeSha256`, the base64 SHA-256 of the zip, as Lambda reports it.
- Deterministic zips (sorted entries, the timestamp 1980-01-01, modes 0644 and 0755), so the same source gives the same `CodeSha256`, and a deploy without changes sends nothing.
- Left out by default: `.git/`, `__pycache__/`, what `.ffignore` names, and `.env*`, with a warning, since it usually holds secrets.

### 5. Output and exit codes (D7)

| Code | Meaning |
|---|---|
| 0 | Success, "no changes" included |
| 2 | A usage error: an unknown flag, a bad argument |
| 3 | Configuration, connection, or an API error that isn't 4, 5 or 6 |
| 4 | A deploy failed: the function didn't become ready; the diagnostics are printed |
| 5 | The invocation failed: the function raised or timed out |
| 6 | Refused by the account, not by the request: no credit (402), a role or a key's scopes (403), the plan's rate (429) |

Text is for people; `--output json` prints one JSON document per command, in a documented shape. Errors go to stderr, with the API's message as the API wrote it, and its request ID when there is one.

### 6. Authentication: an API key first, a login later (D8)
- Every request carries `Authorization: Bearer <token>`: an API key, or a user's token. The API tells them apart; the CLI doesn't need to.
- **First, API keys,** made by an owner in the console with the scopes the commands need. A key acts on its own account.
- **Then `ff login`** (CLI plan, C-40): the OAuth device flow (RFC 8628) against Keycloak's `ff-cli` client, which [ADR 0004](0004-identity-and-tenancy.md) defined and both realm files hold. A user's token names its account with `X-FF-Account`.
- **The development stack** (`FF_AUTH_MODE=dev`) needs no token: the profile's development account goes in `X-FF-Dev-Account`, as `hack/e2e.sh` does.

## Consequences

- A developer's machine holds one secret, their token, which the account's owner can revoke. The platform's keys never leave it.
- The CLI works with the API as it is, except its request limit of about 100 KB, which the CLI plan's C-03 raises.
- `ff local` runs a function in the production runtime image with production's hardening, and hands it the event as the platform does ([ADR 0007](0007-function-events.md)).
- A script or a CI job tells "the account needs attention" (6) from "my deploy is broken" (4) and "my function failed" (5).
- How a zip reaches the pods is a separate decision, made after the CLI plan's C-20 spike: ADR 0003.
- The project file of later phases is an AWS SAM `template.yaml` (the parent's ADR-009), so leaving FF is `sam deploy` with the same file.

## Alternatives considered

- **Keep the Node.js prototype.** It needs Node.js installed, at a version the developer may not have, and installs through npm, which may be slow or blocked; one binary installs anywhere. The parent's ADR-007 decided this.
- **Talk to the object store and the cluster directly,** as the prototypes did. It needs the platform's own keys on every laptop (H-10), and bypasses the API's checks: plans, roles, credit, the audit log.
- **An async HTTP stack (`tokio`, `reqwest`).** Larger binaries and builds, for a tool that makes one request at a time; `ureq`'s streaming reader is enough for the live tail of logs.
- **A `--token` flag.** Convenient, but the token lands in the shell's history and in process listings.
- **FF's own project file (`ff.yaml`).** Customers would learn a format that exists nowhere else, and leaving would mean rewriting it (the parent's ADR-009).
