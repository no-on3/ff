# Step 5's spike: a SAM template's YAML, read in Rust

**The reader is in `ff` now,** as [`cli/src/sam.rs`](../../../cli/src/sam.rs), which `ff doctor` reads templates with and `ff deploy` will (X-12): this copy is the spike's, as it was measured, and `run.sh` still compares it with cfn-flip.

The step-5 plan's X-01, part 4. `ff deploy` will read a `template.yaml` (X-12), and CloudFormation's YAML has short tags (`!Ref Queue`, `!GetAtt Queue.Arn`, `!Sub …`) that each stand for a long form (`{"Ref": "Queue"}`, `{"Fn::GetAtt": ["Queue", "Arn"]}`, `{"Fn::Sub": …}`). `src/lib.rs` is a reader built on yaml-rust2's events: it gives a template as JSON, each short tag in its long form, and where each value starts, by JSON pointer, for messages that name the line. It is a crate of its own, so that the `ff` command takes on no dependency before this spike chooses one.

```bash
hack/spikes/sam-yaml/run.sh      # the reader's tests, then five templates against cfn-flip, about a minute the first time
```

`run.sh` runs the reader's tests, makes `sam init`'s hello-world for Node.js and for Python with the SAM CLI that `hack/install-tools.sh` pins (in a home of its own, where `sam init` keeps the templates it downloads), and compares the reader's JSON of each with what `cfn-flip`, AWS's own converter, makes of it: those two, the Lambda spike's small app (`hack/spikes/lambda/sam/template.yaml`), and two fixtures, `fixtures/every-tag.yaml`, every short tag CloudFormation has in the forms its guide shows, and `fixtures/yaml-1-1.yaml`, the plain scalars YAML 1.1 and 1.2 read otherwise. Its results land in `hack/.spike-sam-yaml/results.md`.

## What it found, on 2026-10-31

With yaml-rust2 0.13.0, cfn-flip 1.3.0 and the SAM CLI 1.169.0:

1. **yaml-rust2's events keep every short tag,** and a reader of about 300 lines builds JSON from them: the five templates read as cfn-flip reads them, value for value: `sam init`'s two, with `!Sub` and `!GetAtt`; the small app, with `!Ref` and `!GetAtt`; the fixture with all 18 tags, `!GetAtt Db.Endpoint.Address` split at its first dot, `!Sub` with its list of variables, `!If`, `!Select` of `!GetAZs ''` and the others; and the fixture of plain scalars. Each event gives its tag's handle and name and a line and column, which the reader keeps by JSON pointer. The other crates: serde_yaml is deprecated, serde_yml is still at 0.0.x, and saphyr, yaml-rust2's successor, had its newest release four days before; yaml-rust2 is the most used of them (about 70 million downloads), its newest release seven weeks old.
2. **CloudFormation reads YAML 1.1, not 1.2:** "CloudFormation supports the YAML Version 1.1 specification with a few exceptions", says its guide, and cfn-flip and the SAM CLI read templates through PyYAML, which is YAML 1.1 too. The reader's first version typed plain scalars as YAML 1.2 does, as yaml-rust2's own loader does, and would have read 12 of the 17 values in `fixtures/yaml-1-1.yaml` otherwise than AWS's tools: `yes`, `No`, `ON` and `off` stay strings in 1.2 and are booleans in 1.1; `0755` is 755 in 1.2 and 493, octal, in 1.1, and `089` 89 in 1.2 and a string in 1.1; `1:30` and `1:30.5` are strings in 1.2 and 90 and 90.5, base 60, in 1.1; `0b101` and `1_000` are strings in 1.2 and 5 and 1000 in 1.1; `1e5` and `1.0e5` are numbers in 1.2 and strings in 1.1, whose exponent needs a point and a sign. So the reader types plain scalars by YAML 1.1's rules, as PyYAML's resolver writes them; a date stays a string, CloudFormation having no timestamps.
3. **What CloudFormation doesn't take, the reader refuses at its line:** aliases and merges (`<<`), which CloudFormation's guide lists among the features it doesn't support, as it does the `binary`, `omap`, `pairs`, `set` and `timestamp` tags; a tag CloudFormation doesn't have (`!GetAttr`, named with the list of those it has); `!GetAtt` without its attribute; a key given twice; a key that isn't a name; a second document; and infinity or NaN, which JSON can't hold. cfn-flip takes aliases and merges, and CloudFormation would refuse them at the deploy: refused before, a template FF takes is one AWS takes too.
4. **A tagged value's column is its text's, after the tag:** yaml-rust2's events carry no position of a tag's own, so `Role: !GetAttr Fn.Arn` is refused at the column of `Fn.Arn`. The line is the tag's, and a message names the line; a column at the tag would mean finding it in the line's text.
5. **The template's own order** is kept with serde_json's `preserve_order` feature, so that messages and a stack's resources come in the order a person wrote them. Cargo turns a feature on for a crate everywhere it is used: in the `ff` command, it would change the order of every map it prints, which its tests check, so X-12 keeps the order beside the value or turns the feature on knowingly.
